# Ноутбуки

Ноутбуки 01–03 запускайте по порядку: каждый читает результат предыдущего. Ноутбук 04 независимый, ему не нужны данные.

| Ноутбук | Шаг | Что делает | Результат |
|---|---|---|---|
| [01_data_collection.ipynb](01_data_collection.ipynb) | ЛР 2, шаг 6 | Загружает данные из OpenStreetMap | `data/raw/*.gpkg` |
| [02_data_profiling.ipynb](02_data_profiling.ipynb) | ЛР 2, шаг 7 | Профилирует и очищает данные | `data/processed/*.gpkg`, сводка качества |
| [03_spatial_analysis.ipynb](03_spatial_analysis.ipynb) | ЛР 2, шаг 8 | Первичный пространственный анализ | `docs/img/*.png`, `docs/maps/*.html` |
| [04_plan_calculator.ipynb](04_plan_calculator.ipynb) | ЛР 3, приложение А | Проверяет PERT, критический путь, загрузку и окупаемость, выводит код диаграммы Ганта | Таблицы для `docs/estimation.md`, `docs/schedule.md`, `docs/budget.md` |
| [05_risk_monte_carlo.ipynb](05_risk_monte_carlo.ipynb) | ЛР 4, шаг 2 | Моделирует срок и трудоёмкость методом Монте-Карло с учётом рисков, считает индекс критичности и EMV для дерева решений. Диск и данные не нужны |

Код написан для учебного примера AquaMap (питьевая вода в Екатеринбурге). Для своего варианта поменяйте параметры в первой ячейке кода и операции анализа в ноутбуке 03.

## Как запустить в Google Colab (основной способ)

Colab бесплатен и работает в браузере, ничего устанавливать не нужно. Подробная инструкция с картинкой процесса — в [приложении Б к заданию ЛР 2](../docs/tasks/lab-2-assignment.md#приложение-б-google-colab-бесплатный-доступ-и-работа-с-проектом). Коротко:

1. Создайте общую папку группы на Google Диске с тем же именем, что у репозитория. Остальные участники добавляют на неё ярлык в «Мой диск». Загрузите туда `data/manual/` из репозитория.
2. Откройте ноутбук в Colab: **Файл → Открыть блокнот → GitHub**, галочка **Include private repos**. Или нажмите кнопку «Open in Colab» в начале ноутбука, заменив в её ссылке `OWNER/REPO` на свой репозиторий.
3. Впишите имя папки в `PROJECT_FOLDER` в ячейке «Настройка среды» и выберите **Среда выполнения → Выполнить все**. Разрешите доступ к Google Диску.
4. Данные и результаты сохраняются на Диск. Последняя ячейка ноутбуков 02 и 03 скачивает архив с результатами: загрузите их в свою ветку через **Add file → Upload files**.
5. Изменённый ноутбук сохраняйте через **Файл → Сохранить копию на GitHub** в свою ветку, не в `main`, а затем откройте Pull Request.

## Как запустить локально (запасной способ)

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
jupyter lab                        # или откройте ноутбук в VS Code
```

Запускайте ноутбуки из папки `notebooks/`. Ячейка «Настройка среды» сама поймёт, что запуск локальный, и будет работать с папками репозитория (`../data/...`, `../docs/...`).

## Правила

- Перед коммитом очищайте вывод ячеек (в Colab: **Изменить → Очистить все выходные данные**, в Jupyter: **Edit → Clear Outputs of All Cells**). Так изменения в PR читаются легче, а репозиторий не раздувается.
- Выводы и цифры переносите в документы (`docs/data-quality.md`, отчёт ЛР 2): ноутбук — это рабочий инструмент, а не отчёт.
- Новый ноутбук называйте с номером: `04_<что делает>.ipynb` и копируйте в него ячейку «Настройка среды» из любого существующего.
- Пути к файлам берите только из переменных `RAW`, `MANUAL`, `PROCESSED`, `IMG`, `MAPS`. Тогда ноутбук одинаково работает в Colab и локально.
